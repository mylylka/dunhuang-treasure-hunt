# 敦煌工程空间优化与历史版本去重方案

## 已做的止增长措施

- 日常试玩使用 `npm run playtest:build` 和 `npm run playtest:serve`。构建不复制 `public/`，服务器从原目录读取共享素材；这不是脱离项目的独立交付包。单次验证构建约 4.7 MiB，原地形独立包每版约 367–430 MiB。
- `.gitignore` 忽略生成的 `outputs/terrain/` 和 `outputs/*.zip`，不改任何已跟踪文件。Codex 的未来内部快照是否一律遵循忽略规则无法保证。
- 项目工作约定已改为不为每次试玩制作完整历史 ZIP、控制截图与工具输出，保留所有现有文件，不自动删除或改写历史。

## 现有重复数据（仅核查，尚未处理）

`node scripts/audit-terrain-duplicates.mjs` 只读扫描 `outputs/terrain/v001` 至 `v013` 的普通文件并计算 SHA-256。13 版合计约 4.93 GiB；完全相同文件的逻辑重复量约 4.35 GiB。单文件不小于 1 MiB 的部分为 68 组、773 个文件实例，其中 705 个是组内重复路径，逻辑重复约 2.52 GiB。

数字是文件逻辑大小，不能保证等量实际释放：APFS 可能已有共享块，也可能受本地快照等影响。审计脚本的 `--json` 可通过重定向导出完整路径清单，不会修改这些文件。

## 可供单独授权的保留版本方案

不直接删除历史版本，可以考虑仅对以上 **705 个、单个至少 1 MiB 的完全相同文件**使用 APFS 写时复制克隆：每组保留一个源文件，用克隆替换其他版本中内容完全一致的文件。各版本原路径和内容保留，之后改写某一版本时仍独立；不用普通硬链接。

执行前需先征得用户明确同意，因为这会逐个替换旧文件。实施时应：

用户已同意执行，并另外知情接受 macOS 在替换后自动更新不可恢复的 inode 状态变更时间（ctime）。创建时间、修改时间、访问时间、权限、所有者和扩展属性仍须校验保留；无法保留的文件跳过。

1. 重新扫描并核验 SHA-256，只处理仍处于 `outputs/terrain/v001–v013`、为普通文件、同一 APFS 卷且满足阈值的候选；符号链接、多硬链接、变动中的文件或异常元数据一律跳过。
2. 先在同目录创建强制写时复制的临时克隆，保留并核对文件元数据及 SHA-256；克隆不受支持或验证失败立即停止，原文件不替换。每个文件的替换使用同目录原子操作，记录成功和跳过的路径。
3. 执行前后核对各版本入口、文件哈希和原有试玩；统计磁盘变化，但说明 APFS 快照与系统回收会使测量波动。若实际收益不明显，应停止扩大范围。

此方案不涉及 `work/build-history` 的 ZIP、用户下载原稿、当前试玩、Codex 会话或 `.git`。ZIP 已核对均非完全相同，且可能含当前工作目录未见的旧源码或素材；会话和差异快照是用户数据，不能当作缓存直接删除。Git 压缩或整理须另做范围和回滚方案，不能等同于本次克隆。

## 2026-11-08 执行结果

用户明确同意克隆替换，并知情接受系统 ctime 更新。先对一份 32 MiB 模型试点，验证哈希、可保留元数据及 APFS 克隆标识后，再处理其余候选；共替换 693 份，另 12 份因创建时间不同而保留原样。去重前后只读清单比较：13 版文件数均为 16,468，重复组路径、大小和 SHA-256 全部一致；13 个版本的入口及其 HTML 直接引用的资源均存在。两处当前试玩入口返回正常。

APFS 报告授权目标的独占空间从约 2,580.50 MiB 降至约 15.66 MiB，减少约 2,564.84 MiB；693 份替换文件与各自源文件具有相同克隆标识、各自独占数据为零。系统整体可用空间仍随其他占用波动，不能将此差值等同于 `df` 同时增加的空间。只读清单、逐项日志及前后测量存 `work/storage-optimization-v001/`。

核查时系统可用空间仍约 0.3 GiB，macOS 报告 swap 总量 17 GiB、已使用约 16.3 GiB；swap 属系统管理，未删除或更改。历史 ZIP、Codex 会话、Git 对象和用户原稿未作清理。
