# 敦煌寻宝记文件存放约定

| 用途 | 存放位置 | 整理规则 |
| --- | --- | --- |
| 原图、原始模型、录音、定稿设计素材 | 仓外素材库、既有 `art-source/` | 原有归档按原路径查阅。新入库的原件按 SHA-256 保存，`art-source/` 按场馆、用途和版本登记来源、原件和派生文件。已存的同一原件直接引用。 |
| 游戏实际读取的图片、模型和音频 | `public/assets/` | 放裁剪、压缩、切片后的运行版。按用途及版本命名。清理前核对现版与留存版本的引用。 |
| 设计稿、素材说明、验收结论和版本修改记录 | `docs/` | 按主题组织。历史记录使用 `docs/history/`，可引用原稿或验收图。 |
| 待选择的生成图和设计对比图 | `work/design-candidates/<任务或版本>/` | 候选用编号，选定后把定稿及其来源登记进原稿目录。候选目录单列整理，不纳入定时清理。 |
| 人工验收截图 | `work/qa/screenshots/<任务或版本>/` | 保留能说明结果的最终视角。文件名区分桌面、手机和对比视角。验收记录引用具体文件。 |
| 自动测试输出 | `work/test-results*` | 默认关闭浏览器回放。需要调试时显式开启。已识别的回放包满 7 天后清理，测试脚本及验收文字另存。 |
| 临时 2D 试玩包 | `work/temporary-2d-playtests/` | 日常直接启动当前源码。临时 ZIP 需要专用命名和包内标记，满 48 小时后清理。 |
| 当前可运行成品及旧 3D 版本 | `outputs/web/`、`outputs/terrain/`、已登记的 3D 构建目录 | 目录有各自入口和引用。旧 3D 留档继续按原路径启动，明确留档时才生成新构建。 |

原稿和运行资源即使名字相似，也分别承担编辑和播放用途。用户下载目录的文件只有经过完整副本核对后，才能列入单独的整理清单。此前混放的目录按实际用途和引用逐项清点，移动前一并核对文档、脚本和旧版入口。

新素材库默认位于 `~/Documents/DunhuangAssetLibrary/`，可在运行导入工具时通过 `DUNHUANG_ASSET_LIBRARY` 指定仓外位置。首次使用先登记目录约定。`objects/` 按内容哈希存原件，下载与转换使用工具自己拥有的临时文件，验证成功后发布。素材库须随项目备份，换机可通过仓内清单核对完整性。下载前先核对已登记的来源和哈希。派生复用按原件哈希、转换参数与工具版本判断，更新内容使用新的版本路径。

纹样教学参考图、第二馆一楼壁画、第一馆图鉴、第二馆导游模型和飞天配音已接入 `scripts/asset_intake.py`。仓内清单用 `vault:sha256:<哈希>` 指向新原件，已有相对路径继续读取。首次接收壁画或图鉴附件时，把附件目录传给对应脚本。核对已登记版本时可省略附件参数。旧运行图缺少哈希时按既有格式、尺寸及已登记字节数核验，新导出登记完整哈希。相同图片用于另一个展示位置时，优先直接引用已有运行图地址。视频等本地原件可用同一入库入口及相应的格式校验，已有视频运行版按原清单读取。

```sh
python3 scripts/import-pattern-lesson-references-v002.py
python3 scripts/prepare-music-ground-floor-mural-v001.py /path/to/attachments
python3 scripts/prepare-first-gallery-folio-v001.py --import-from /path/to/attachments
python3 scripts/prepare-music-guide-v001.py --check
python3 scripts/build-flying-history-audio-v001.py --check
```

已盘点的 32 处历史试玩 `assets/` 构建目录列入 `.gitignore`，同目录的入口、交接说明和审阅文稿仍可按原路径查阅。历史目录中其他文件按具体用途认定，避免将设计源或交接资料归入生成物。

临时包、测试回放与项目历史分别管理。内部试用的服务验证完关闭，交付用户的端口在验收结束或新版接替时关闭。早期 2D 版本的历史索引位于 `docs/history/early-2d/`，用于查阅当时的文稿、代码记录和验收图。
