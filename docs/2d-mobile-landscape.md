# 2D手机横屏支持策略

2026-11-03，用户明确停止维护手机竖屏可玩界面，以减少开发和测试开销。旧布局代码、原图、截图和历史验收记录保留。

## 原项目当时的行为与边界（历史记录）

- 主题选择、文化导览、玩法/关卡、五种玩法和结果统一采用手机横屏。帮助/设置普通访问，电脑窄窗口不被误锁，3D方向规则独立。
- 手机识别结合设备屏幕CSS短边≤600px、触控、粗指针及无悬停；方向按实时视口宽高判断。兼容WebKit触控事件能力，监听媒体查询、resize、orientationchange和visualViewport.resize，不调用系统方向锁。
- 初始竖屏不挂载内容；已开局竖屏保留组件与同一Phaser实例，原生顶层modal统一提示并阻挡输入，横屏恢复布局。找物结算阻挡前耗时后停表，回横屏仍暂停，玩家主动点“继续寻找”。
- 拼图撤回未落位拖拽；填色保留已接受颜色；找不同保留发现与提示级别；影子保留顺序和错误。释放指针捕获，不伪造pointerup或完成事件。观察窗隐藏时忽略零尺寸，保留缩放和平移。
- `mobile-landscape.ts`提供同步快照；`MobileLandscapeGuard`仅在上述2D路由挂载，阻挡时hidden/inert保留内容，并捕获点击/input/change。公共宿主调用五种控制器的`setBlocked`生命周期接口，不占用命令序号、不因方向变化重建，阻挡时清理旧命令并冻结尺寸，异步ready补应用阻挡。
- 未修改存档结构或3D运行器。现有手机竖屏样式与记录为历史，不再作为可玩承诺。

## 本轮实际验证

- 内容校验、类型检查、构建通过。
- `npm run test -- tests/unit/mobile-landscape.test.ts tests/unit/scene-blocking.test.ts tests/unit/shadow-match.test.ts`：23项通过，覆盖设备识别、同步订阅与清理、五种Scene、时钟及局面保留。
- `tests/e2e/mobile-landscape.spec.ts`：Chrome手机8个方向场景分批覆盖通过，含所有2D入口、电脑窄窗、五种玩法（两种拼图）、拖拽中断、停表及观察窗。首轮6项通过；发现隐藏按钮被分发点击时可先改变React状态，补充统一捕获阻挡后两处隔离复验通过，原断言/超时保留。
- Safari/WebKit手机3项通过：初始入口、找物中断、观察窗缩放和平移。补充触控能力、实时视口与方向/visualViewport事件兼容。固定screen的WebKit模拟会冻结CSS布局视口，方向专项改用随viewport旋转的screen，保留中心命中等断言。
- 手机横屏旧流程定向6项通过：填色参考/换色/撤销/清空/刷新/PNG、找不同完成保存、找物真实点击保存、旋转拼图、不规则拼图与影子配对，输出`work/test-results-mobile-landscape-supported-flows/`。
- 未跑全量规则、全套E2E、全套生产或3D回归。浏览器检查串行执行，失败trace保留。旧测试不skip、不放宽0.999可见比例、真实操作及保存断言。

手机项目默认844×390，备用640×360；竖屏只验证统一提示与中断保局。桌面context下360×640明确为桌面窄窗，不冒称真实手机竖屏。已查看`outputs/2D手机竖屏-横屏提示.png`与`outputs/2D手机横屏-恢复游玩.png`。
