# 找物加载与二维空洞修复

2026-11-04，针对手机进入游戏/各关约半分钟等待，以及“生灵寻踪”首屏左中大块空白的反馈。保留九关配方、120件、1.2～1.6尺寸、约±24度旋转、50秒、精确同图与原完成记录；不做玩法或界面重设计。

## 根因及基线

- 原手机试玩直接使用Vite开发服务。一次冷开第二章的受控Chrome测量（8Mbps下载、35ms延迟、CPU 4倍减速）传输74,955,901字节、407个请求，首次内容绘制20,948ms，开始按钮可用76,415ms。报告为`work/hidden-object-load-before.json`。这是真实浏览器的限速模拟，不是iPhone实机计时。
- `index.html`先进入地形预览，2D深链接也下载Three及预览依赖，再导入React主入口。开发模块、内联调试信息及Phaser体积远大于正式构建。
- 首次React渲染前，`loadCatalog`同步为九关各试摆两种种子。桌面Node中约626ms；每关还要为本局另生成一次。
- 原v002贴纸520张共98,956,872字节，第二章每局约30MB贴纸，另有约1.72MB底图；Phaser等待全部图片，再同步读取120张RGBA生成命中蒙版，才公布目标。
- 原密度门槛仅测全宽300/600px横带，左空右密会抵消。生灵寻踪seed74虽通过旧横带门槛，左中320×300局部覆盖26.6%，整盘约67.2%。

## 实现边界

`src/bootstrap.ts`让2D深链接直接进入主入口，默认首页仍执行原地形预览初始化。HTML先提供浅色的即时启动面，模块失败保留重试；实际等待时间另外测量，不以启动文案代替性能改善。

`loadCatalog`使用runtime模式，保留结构、引用、图库、尺寸、配额和全部可抽任务组合的可完成性检查；不生成全部关卡的坐标。内容CLI/构建仍做真实多种子深检，默认`parseCatalog`继续深检以保持旧调用语义。桌面Node测量runtime冷36ms、热12～29ms；这不是手机时延承诺。

素材另存q92 WebP技术派生，保持完整尺寸、原画内容及逐像素相同的alpha，不裁切、缩小、镜像或重绘。RGB使用有损高质量编码，不声称与原PNG逐字节相同；原PNG和原索引快照不覆盖。任务卡与对应实例通过同一纯路径映射使用同一WebP，精确sprite ID规则不变。正式派生体积/质量见v004贴纸和v002底图manifest；样本原尺寸及180px对照在`work/hidden-object-webp-*.png`，指标在`work/hidden-object-webp-quality.json`。

Scene在preload发布本局真实目标，并优先排入目标图片。准备页可先显示目标，全部资源成功前开始按钮disabled、不扣时；失败保留重新加载。点击命中的alpha蒙版按实际点击图片延迟读取并缓存，不再在开局同步读取120张纹理。

散放候选统计由3×6细分到6×12，仅作面积评估，不作位置吸附。剔除不可能容纳任何剩余物件的自由矩形，减少两两包含检查；原14轮摆放预算保留。整盘通过原300/600px横带门槛后，最多24步合法连续移位，最终要求320×300二维滑窗（x步80/y步75）占用至少为全盘平均的65%，20px采样点到最近旋转AABB距离不超过65逻辑px。移位不能改变图、大小、角度，不能发生遮挡或越界；填一处后仍检查其它区域，耗尽原预算则明确报错。新一局生成异常也进入可重载错误页并停止输入，不能停在无反馈的加载层。

`npm run play`使用`scripts/serve-preview.mjs --port=5173 --no-open`提供正式构建：脚本/CSS/JSON支持Brotli或gzip，HTML重新验证，版本化图片及哈希构建块可缓存；支持HEAD/ETag/音频字节范围，不影响已有4186启动方式。5173试玩需要先构建，日常开发仍可使用Vite。
