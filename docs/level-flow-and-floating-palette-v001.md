# 关间导航与可拖动色盘

2026-11-03，用户确认找不同主画布缩放后，要求移除重复观察入口、统一关间流程、修正题名断行，并将填色完整色盘改为不遮画布的初始浮窗。当前约定已包含同日后续批注：常驻纯文字上一关/下一关、取消说明型菜单、统一弹窗外缘与关闭按钮；色盘手动拖动后允许覆盖画布。

## 关卡流程

- `getPreviousOpenLevel`和`getNextOpenLevel`使用选关目录顺序，只取同主题、同玩法的实际开放关卡，跳过筹备位，不循环。
- `LevelNavigationProvider`向游玩与结果路由提供实际相邻关；`LevelAdvanceControl`不发完成命令。游玩主页面常驻同字体、同颜色的纯文字“上一关”“下一关”，移除装饰按钮底图及主次按钮皮肤。首关的上一关、末关的下一关，以及单关的两项均保留原生disabled按钮，没有href，不替换成目录链接。找物准备页只突出本局目标与开始入口，导航在开始后出现。
- 点击任一相邻关只导航、不写通关；填色已有自动保存作品保留，不伪提交；离开找物销毁原计时实例。测试标记为`level-previous`与`level-advance`，真实链接提供对应的相邻关ID。
- 五种玩法完成页的第一枚、唯一主色按钮统一为“下一关”；末关/单关为“返回关卡”。重玩与仍有下一关时的目录入口为次要按钮。既有通关门禁和存档结构不变。
- 找不同仅保留主画布双指/按钮同步缩放，移除该玩法的独立观察入口与页面调用。旧组件文件和历史图片保留，教学、拼图参考与影子对照窗不受影响。
- 手机窄栏四字标题按两个完整双字词组显示；“双龙藻井”使用“双龙／藻井”两行。拼图直接提供“查看原图”“重新拼图”；填色直接提供“清空重涂”，两者的说明型更多菜单及入口均取消。手机填色右侧保持简洁纵向操作栏，返回只显示原箭头图标，保留完整无障碍名称与44px触点。

## 完整色盘

`FloatingColorPalette`是非模态`section role="dialog"`，不调用`showModal`、不锁定主画布、没有整页遮罩。首次/重新打开使用参考色盘栏与操作栏的联合范围放置，约210×250px，完整显示12色及自由选色，初始不盖画布。复用现有面板彩色线条装饰，背景透明，不添加外围白衬边。

自由选色为44×44px的正圆彩虹渐变，透明的真实`input[type=color]`覆盖其上，保留原生颜色选择与键盘访问。选颜色后浮窗保持打开，画布露出的区域可以直接继续填色。

按住标题栏可使用触屏/鼠标拖动整个浮窗；主动拖动后可在整个网页视口移动，允许盖在画布上方，但窗体夹取在视口内。方向键每次移动10px，Shift为30px，Home回到右侧，Esc关闭。拖动使用原生指针捕获，不向画布转交点击；失焦、后台、取消和竖屏阻挡取消拖动。窗口变化夹取旧位置，重新打开复位。纯位置规则在`src/runtime/floating-panel.ts`，不改图像或着色数据。

## 保留弹窗的外框与关闭

`dialog-chrome.css`只覆盖非3D首页内的实际2D装饰弹窗：教学资料、教学图片观察、拼图原图、填色参考、影子对照和完整色盘。外层背景与边框底色透明，继续使用原装饰PNG和`border-image-slice: ... fill`，避免整块浅色背景透过PNG外围形成白边；不改变安全间距、不裁掉控件，教学内层浅色内容面保留。统一竖屏提示、3D和找物用于遮住盘面的准备/暂停层不在这条透明规则内。

关闭统一使用`DialogCloseButton`的内联SVG线条叉号，实际触点44×44px。`App`通过DOM dataset记录输入方式：pointerdown/touchstart为pointer，导航键为keyboard，不逐次更新React状态。2D指针操作不绘制键盘焦点方框，键盘轮廓保留并使用暖色；关闭按钮采用圆形焦点。2D入口与来源文字移除系统emoji斜箭头，图片放大功能继续保留。

## 移动音效诊断

已经证实的代码缺陷有两处：旧全局监听只在pointerdown申请解锁，而[WebKit列出的触屏激活点](https://webkit.org/blog/13862/the-user-activation-api/)是非鼠标pointerup或touchend；旧播放器又复用一个未完成的resume Promise，挡住后来有效手势的再次调用。[Web Audio规范](https://www.w3.org/TR/webaudio-1.0/#dom-audiocontext-resume)允许未获准启动的resume保持pending，因此不能靠等待它reject来恢复。

现在在真实触屏抬起/点击和鼠标/键盘手势中同步创建或恢复原生AudioContext；新手势可以重新resume，旧失败不撤销新成功。解码与恢复独立完成，只启动仍有效的最新反馈；停止、静音或超过650ms的反馈不会迟补。blur、hidden和pagehide取消反馈，focus/pageshow不自动发声。原七段音效是有效的44.1kHz、单声道、16位PCM WAV，数据有非零样本；声音资源、默认开启40%及已有静音/音量偏好均未更换。

这些是可以复现并修复的代码原因，不能据此断言已排除用户那台iPhone的全部无声原因。`sound-mobile-unlock.spec.ts`观察真实构造、resume Promise、source.start、非零样本/RMS与WAV请求，用touchscreen.tap验证首响和真实suspend后的恢复，并检查关闭或零音量偏好不被绕过；不伪造播放许可。API与波形检查不等于实机扬声器或耳机已听测。

## 定向检查

规则检查覆盖五玩法顺序隔离、筹备位/末关/单关、2+2题名、初始侧栏范围、拖动边界和窗口变化。浏览器专项分别覆盖跳关不通关、填色自动保存不提交、五玩法主按钮顺序、640×300和852×330可见触点，以及色盘初始不盖画布、正圆渐变、拖到画布上方不误涂、浮窗开着真实填色、键盘复位和方向恢复。

原有找不同观察测试迁移为主画布同步缩放/移动/复位，B的配置区域合成、真实差异命中和存档断言保留；拼图直接验证主页面原图/重来，填色直接验证清空，并断言旧说明型菜单不存在。常驻前后关测试保留真实前进、键盘返回、首末disabled无href、同字体颜色、44px与0.999可见比例，以及旧记录不变；填色旧完整流程通过关闭非模态色盘后继续按钮操作，不强制点击被遮住的按钮。

本轮不跑3D回归、全量E2E或全量生产验收。浏览器模拟不替代iPhone实机试玩。
