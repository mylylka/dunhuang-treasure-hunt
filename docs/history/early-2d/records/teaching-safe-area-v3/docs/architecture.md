# 架构与继续开发

## 当前边界

React 负责导航、文化教学、玩法与关卡选择、提示面板、结果和长期记录；Phaser 4.2.1 负责当前关卡的图像和输入。主题引用玩法，不为每个主题复制玩法代码。正式关卡目前只有 `patterns-intro`；纹样主题的七屏教学已经接入，其余主题展示未开放。

## 屏幕与布局

应用占据当前动态视口（`100dvh`），首页、文化教学、玩法选择、该玩法关卡、游玩和结果是独立屏幕，使用 hash 路由切换。页面主体不纵向滚动；手机首页通过主题按钮切换封面。关卡目录按实际可用空间展示6、3或2张卡片，超过当前容量后分页；桌面常规视口同时展示六关，手机分页。帮助、教学正文和资料弹窗可在专用文字区域内部滚动。

`src/app/navigation.ts` 集中管理路由解析与路径。`#/` 是主题首页；`#/theme/patterns` 是文化导览；`#/theme/patterns/games` 是三种玩法；`#/theme/patterns/games/spot-difference` 是找不同关卡；`#/play/patterns-intro` 与结果地址保留稳定关卡ID。首次直接访问玩法或游玩地址会引导先看文化导览，不破坏旧游戏完成记录。

`ThemeCards`、`TeachingScreen`、`GameSelectScreen`、`LevelSelectScreen` 各管一层界面。三张主题卡共用相同3:2图框与14px图文间距，不能让全高容器把标题推到屏幕底部。装饰按钮使用独立正文容器，正文以按钮真实中心对齐，方向符号不参与正文居中。

游玩页给导航、操作和提示保留空间，剩余区域交给 Phaser。运行器同时观察容器的宽和高，比较并排和上下两种排法，选择图片能显示得更大的方案，将两张完整的 3:2 图按比例放入。容器尺寸变化只重新布局，不重建本局状态；手机横屏隐藏站点页眉与页脚，为画面留出空间。

## 内容入口

- 正式主题：`src/content/themes.json`。
- 素材索引：`src/content/assets.json`。
- 关卡：`src/content/levels/*.json`。Vite 自动发现该目录的 JSON；增加同玩法关卡无需改运行器。
- 配置和语义校验：`src/services/content-schema.ts`。
- 教学类型、内容和注册：`src/content/lessons/`；教学配置语法及引用校验：`src/services/lesson-schema.ts`。
- 公共接口：`src/types.ts`。

教学书按主题注册，包含稳定ID、内容版本、章节、面板、观察区域、提问和来源。第一主题七章为装饰部位、花叶纹样、几何纹样、动物纹样、组织方式、色彩、观察回顾。教学整体使用有明亮底色、U03装饰边框与阴影的悬浮面板，面板内有“文化导览”标识和七个页签。图像热点和放大区域使用0～1比例坐标；通用教学组件不硬编码某个窟号或文字。新增面板主要修改内容数据，新增交互类型才扩展组件。

首次完成导览后开放玩法选择，不再以找不同入门关的完成记录作为前提。`introLevelId` 仅保留内容语义，不控制这层导航。图片以稳定素材ID引用，`version` 用于缓存标识；来源和占位状态随资源登记。未实现的拼图、填色禁用，不显示空的可玩入口。

## 找不同的显示方式

左侧为 A 图。右侧仍以 A 为底，只在配置区域内覆盖来自 B 的对应片段。差异数量来自数组长度；配置只有两项时，只出现两个视觉改动。图片完整等比显示；差异区域相对图片记录为 0～1 坐标，留白不参与命中。界面和玩法之间仅传命令和事件，不逐帧共享状态。

当前首关使用用户交付的五处差异。运行 B 图预先以 A 为底、在五个区域内用物象蒙版合入 L02，排除其他重绘漂移；Phaser仍保留局部覆盖保护。“放大观察”是独立只读组件，切换A/B和通用2倍区域，不改变发现状态；返回后继续在原图点击。

## 进度

`dunhuang:progress:v1` 保存完成记录与减少动效设置。每次完成幂等写入；重开只重置本局。无法保存时保留本次内存状态并显示重试。未来作品数据与小型进度分开接入，不存储图片到当前进度键。

`dunhuang:learning:v1` 独立保存各教学书的内容版本、已访问章节与导览完成时间。首次需要看过七屏并参与最后三道回顾题，答错也可看解释并继续；完成仅代表参与，不代表知识掌握。未完成时可从已有章节记录继续，再访已完成导览可直接选游戏。内容版本变化会使该书的旧完成记录失效，不影响游戏进度。读写失败如实提示并提供重试；损坏原记录在受保护写入前先备份，备份失败不能覆盖原数据。

## 新增玩法

在 `src/games/` 下增加该玩法的规则和场景，通过运行器接入；为该玩法单独增加配置校验和关卡样板。公共命令与事件先满足真实使用，再扩展。故事拼图与空间拼图可以共享拖放工具，但完成判定分别实现。

## 验证与本地预览

依次运行项目 AGENTS.md 中的内容校验、类型检查、Vitest、Playwright 与构建命令。`npm run dev` 提供本地和局域网预览；正式构建输出到 `outputs/web/`。公开部署、全局依赖与系统配置遵守用户红线。

## 素材协作

全部15项当前美术已由婧婧提供并接入。原稿按v001保存在 `art-source/`，运行PNG进入 `public/assets/`，旧几何SVG保留但不再引用。`delivery-v001.json`记录原名、尺寸与SHA-256；技术导出脚本见 `scripts/import-art-v001.py`，正常npm开发无需Python。图像属于AI教学示意，不是第329窟的精准复原；内容性修图继续由婧婧制作。

另有教学参考图，原文件与来源记录在 `art-source/references/patterns/v001/`，运行图在 `public/assets/lessons/patterns/`。保留源图水印与真实分辨率，不以AI补画冒充实物。用户补充的第254窟平顶用于平棋与忍冬讲解；三兔拼版在资料弹窗补充展示。无水印更新在v002归档：第329窟使用机构供图，第407窟实物边带用于菱格。带水印且出处未核的忍冬整理图退出展示，原文件保留；未核实的原始出版信息明确保留待补状态。

## 规划目录与结果页

`src/content/level-roadmap.ts` 保存第一批六关计划。`getLevelChoices` 以稳定ID与实际内容目录合并，实际目录决定是否可玩；没有正式配置的规划位只显示“筹备中”，没有链接、完成标记或写入进度的行为。新增真实关按ID接替规划位，未列入计划的真实关仍追加显示，不被规划表丢弃。

结果页直接显示文化参考链接、简短观察知识与“开发者使用AI生成”的说明。逐条差异分析和其弹窗入口已移除；`explanation` 在历史配置兼容中为可选，首关已不保留五段分析。游玩提示、点击区域、完成判定与原进度结构不受影响。
