# 架构与继续开发

## 当前边界

React 负责导航、学习目标、提示面板、结果与本地进度；Phaser 4.2.1 负责当前关卡的图像和输入。主题引用玩法，不为每个主题复制玩法代码。正式目录目前只有 `patterns-intro`，其余主题展示说明。

## 屏幕与布局

应用占据当前动态视口（`100dvh`），首页、主题选关、游玩和结果是独立屏幕，使用 hash 路由切换。页面主体不纵向滚动；手机首页通过主题按钮切换封面。关卡按页展示，依据列表可用高度与实测卡片高度计算容量，每页最多三关。帮助和文化介绍允许在专用文字区域内部滚动，关闭后回到原屏幕。

游玩页给导航、操作和提示保留空间，剩余区域交给 Phaser。运行器同时观察容器的宽和高，比较并排和上下两种排法，选择图片能显示得更大的方案，将两张完整的 3:2 图按比例放入。容器尺寸变化只重新布局，不重建本局状态；手机横屏隐藏站点页眉与页脚，为画面留出空间。

## 内容入口

- 正式主题：`src/content/themes.json`。
- 素材索引：`src/content/assets.json`。
- 关卡：`src/content/levels/*.json`。Vite 自动发现该目录的 JSON；增加同玩法关卡无需改运行器。
- 配置和语义校验：`src/services/content-schema.ts`。
- 公共接口：`src/types.ts`。

主题用 `introLevelId` 指定入门关，完成记录推导解锁。图片以稳定素材 ID 引用，`version` 用于更新缓存标识；原稿来源和占位状态随资源登记。

## 找不同的显示方式

左侧为 A 图。右侧仍以 A 为底，只在配置区域内覆盖来自 B 的对应片段。差异数量来自数组长度；配置只有两项时，只出现两个视觉改动。图片完整等比显示；差异区域相对图片记录为 0～1 坐标，留白不参与命中。界面和玩法之间仅传命令和事件，不逐帧共享状态。

## 进度

`dunhuang:progress:v1` 保存完成记录与减少动效设置。每次完成幂等写入；重开只重置本局。无法保存时保留本次内存状态并显示重试。未来作品数据与小型进度分开接入，不存储图片到当前进度键。

## 新增玩法

在 `src/games/` 下增加该玩法的规则和场景，通过运行器接入；为该玩法单独增加配置校验和关卡样板。公共命令与事件先满足真实使用，再扩展。故事拼图与空间拼图可以共享拖放工具，但完成判定分别实现。

## 验证与本地预览

依次运行项目 AGENTS.md 中的内容校验、类型检查、Vitest、Playwright 与构建命令。`npm run dev` 提供本地和局域网预览；正式构建输出到 `outputs/web/`。公开部署、全局依赖与系统配置遵守用户红线。

## 素材协作

正式美术原稿和 AI 改图由婧婧提供，Agent 不自行生成替代原稿。当前几何 SVG 是明确标注的技术占位。接收规范见 `docs/art-assets.md`。参考第329窟的教学重绘尚待用户制作，不能把占位几何当作历史图像。
