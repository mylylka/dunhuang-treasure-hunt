# 《敦煌寻宝记》工作约定

## 产品与实施范围
- 面向高中生的本地优先网页小游戏，电脑和手机均可使用。
- 三主题：纹样与色彩；飞天、乐舞与服饰；壁画故事与宗教文化。
- 每主题完成自己的入门关后，开放该主题其他已制作关卡。未制作的内容明确标记，不创建空的可玩入口。
- 首批实现公共框架与找不同入门关。无限提示与重试；无倒计时、无扣分、无收藏系统。
- 采用 Phaser 4.2.1、React、TypeScript、Vite；项目内 npm 依赖，本地 CLI 开发。

## 先有规则，再有实践
- 新增目录须符合下列约定；调整结构时先修改本文。
- `src/app/`：导航、页面和公共 React 界面。
- `src/runtime/`：Phaser 生命周期、画布布局、界面通信。
- `src/games/`：按玩法隔离规则、场景和局内状态。
- `src/content/`：正式主题、素材索引和关卡 JSON；稳定 ID 不随顺序改变。
- `src/services/`：配置校验、进度与设置存取；`src/styles/`：主题色、排版及界面样式。
- `public/assets/`：游戏运行素材，按 `shared/`、`themes/`、`levels/<level-id>/` 分类。
- `art-source/`：用户提供的原尺寸美术与图源说明；原稿保留版本，不覆盖或删除。
- `tests/`：规则测试、浏览器测试与独立测试素材；测试关不得进入正式目录或正式存档。
- `scripts/`：内容校验、构建辅助和打包工具。
- `docs/`：架构、素材接入与维护说明。
- `work/`：中间脚本、检查结果、截图、日志和测试缓存；清理前遵守用户的删除审批要求。
- `outputs/`：用户可取用的构建结果、交付文档和源码包；不放临时文件。
- 文件采用英文 kebab-case；React 组件采用 PascalCase；代码变量采用英文，文档与界面默认中文。

## 美术与内容边界
- 所有正式美术原稿和 AI 改图由婧婧在 ChatGPT 网页端生成。
- 当前允许 Agent 使用清楚标明“待替换”的几何占位图验证功能，不将其当作正式敦煌美术。
- Agent 负责规格、提示词、图源整理、格式处理、坐标标注、技术整合和验证；内容性修图交回用户。
- 正式图源以莫高窟第329窟初唐莲花飞天藻井为首关参考；占位图不声称复原任何文物。
- 首关源图与运行图均为 3:2；素材 A/B 尺寸一致。图片以原图比例坐标标注，游戏内容完整显示，不裁切。
- 变化图在运行时以 A 为底，仅覆盖 B 中已确认的三个差异区域；检查区域边缘、色调与对齐。
- 素材更新必须同时检查标注、提示、缓存版本与手机可读性。

## 架构纪律
- 主题引用玩法，禁止按主题复制一份玩法代码。
- React 管界面与长期记录；Phaser 管局内状态。两者经类型明确的命令和事件通信。
- 局内规则尽量使用不依赖 React/Phaser 的 TypeScript 函数。
- 离开关卡销毁实例并清理监听；异步加载完成后不得操作已销毁的实例。
- 解锁由入门关完成记录推导；保存失败须如实提示，不显示“已保存”。
- 不引入账号、服务端、数据库迁移、云同步或未经确认的公开部署。

## 必须完成的验证
- `npm run validate:content`：正式关卡、图像、比例和区域检查。
- `npm run typecheck`：TypeScript 检查。
- `npm run test`：Vitest 规则、配置与存档测试。
- `npm run test:e2e`：Playwright 电脑、手机、提示、重试、保存与解锁检查。
- `npm run build`：生产构建。
- `npm run test:production`：构建后实际检查皮肤/背景网址、1440→360布局、操作和保存，输出用户预览截图。
- 修改后运行与变更相应的验证；不得注释报错、跳过关键断言或用绕过标记掩盖问题。
- 第二份关卡配置仅在测试环境注入，使用隔离存储，验证两处差异与独立进度；不宣称其余玩法已实现。
- 浏览器模拟手机检查后，交付局域网地址供用户实际手机试玩；公开发布另行确认。

## 用户红线
- 删除文件、目录、Git 历史；修改 .env、密钥、token、CI/CD；数据库 schema 变更或迁移；git push/rebase/reset --hard/强推；全局依赖或系统配置；公开发布：均须事先取得明确授权。
- 不将密钥、token、密码写入代码、提交或日志。
