# 美术素材接入与替换

## 当前状态与分工

当前 15 张 SVG 都是**占位素材 / 非正式美术**，由 Agent 用几何形状创建，只用于验证布局、交互、加载与找不同判定。它们不代表敦煌原壁画、正式教学重绘或历史配色。素材索引均记录 `placeholder: true` 和 `version: placeholder-v1`。

- **婧婧**：在 ChatGPT 网页端生成所有正式原稿与内容性改图，确认整体风格、构图和三处有意义的差异。
- **Agent**：给出规格、提示词、图源与制作清单；核对图像属性、透明通道与尺寸；生成运行版、标注点击区域、整合和验证。需要改变人物、纹样、配色内容时交回用户修改。

## 原稿、透明背景与文字

所有正式原稿按 `art-source/README.md` 保存版本，不覆盖或删除旧原稿。运行素材和原稿分开。

- 透明图标、按钮外边缘和面板外边缘使用**真实 alpha 透明通道**；把棋盘格画进图片不是真透明。
- 背景和关卡图可以是完整不透明画面；当前运行素材与尺寸校验采用 PNG 或 SVG。正式 AI 原图建议交付 PNG。
- 按钮名称、提示、知识说明等由程序排版，正式底图不烘焙界面文字。当前占位标记在正式图接入时替换。
- 图标在统一画布中保留边缘留白，视觉主体居中；透明留白不能直接当作物体的可见轮廓。
- 参考图现存颜色不等于创作时原貌。AI 教学重绘和真实史料在来源说明中分别标明。

## 面板与按钮的九宫格约定

九宫格是把底图切成四角、四边和中心：角保持形状，边沿单方向伸展，中心填充。这样尺寸改变时不会把圆角和装饰一起压扁。

- 面板 `1024×1024`：建议切线 `x=128/896`、`y=128/896`；四角的重要形状放在对应角区，中心 `768×768` 使用可平铺或可伸展的低对比纹理。
- 按钮 `1024×256`：建议切线 `x=96/928`、`y=64/192`；左右端装饰不得侵入可伸展中心。
- 当前占位素材的实际切片是：面板四边72px，按钮上下64px、左右80px。正式图的实际切片写入素材索引的 `slice: {top, right, bottom, left}`，界面自动读取，无需修改CSS。以上建议128px角区仅供生成时控制装饰范围，接入时以实际图为准。
- 正式交付时确认切线是否适合新图，并把实际值写进该版本的素材说明。技术整合时使用九片或等效边框绘制；不将整幅底图任意非等比拉伸。
- 图标、封面、背景和关卡图不采用九宫格；关卡图完整等比显示，不能为铺满区域而裁掉画面。

## 首关 A/B 与三个差异区域

文化参考是敦煌研究院的[莫高窟第329窟初唐莲花飞天藻井](https://www.dha.ac.cn/info/1425/3577.htm)。官方资料说明该窟开凿于初唐，窟顶有莲花飞天藻井，井心以外有卷草纹、联珠纹等装饰。**当前几何占位图不描绘该文物，不能据此给占位图追加历史细节。**

占位图 A/B 使用同一画幅和公共底图，只有三处形状发生变化。下面坐标基于完整运行图，范围为 0–1：

| 差异 ID | 当前观察内容 | x | y | width | height |
|---|---|---:|---:|---:|---:|
| `leaf-missing` | 上方一个叶形重复单元缺失 | 0.12 | 0.10 | 0.20 | 0.23 |
| `petal-outline` | 中央向上花瓣的轮廓变化 | 0.42 | 0.35 | 0.20 | 0.30 |
| `vine-direction` | 右下卷曲枝叶朝向变化 | 0.69 | 0.67 | 0.20 | 0.23 |

这些坐标只对应当前占位图。用户提供新图后重新标注，不把旧坐标机械套入新构图。提示、详细提示、解释与实际差异一起审校。

### B 的局部合成

1. 先确认 A/B 尺寸、比例、构图和像素对齐一致。
2. 两图的标签、画布、边框和不应变化的内容保持一致，避免出现第四处意外差异。
3. 运行时以 A 为底，只从 B 取已确认的三个区域覆盖到相同位置；其他部分继续使用 A。
4. 检查三个覆盖块的边缘、色调、纹理和对齐，避免明显方形接缝。真实纹样若跨出原区域，扩大或重画区域，并检查它与其他目标是否重叠。
5. 确认 PC 和手机的全图都能观察到差异，放大后的触控区域仍跟随图像；颜色变化不能成为唯一线索。

## 正式图替换步骤

1. 婧婧提供同一版本的 A/B 原稿和来源说明，先放入新的 `art-source/levels/patterns-intro/vNNN/`；原稿不覆盖。
2. Agent 检查文件可读性、尺寸、比例和 alpha，再导出同尺寸运行图。运行文件采用新文件名，例如 `patterns-intro-a-v002.png`，保留现有版本。
3. 保持素材 ID 不变，在 `src/content/assets.json` 更新路径、真实宽高、版本、`placeholder: false` 和 `sourceNote`。版本号/文件名同时变化，避免浏览器继续使用旧缓存。
4. 更新 `src/content/levels/patterns-intro.json` 的三个差异区域、提示和解释；核对文化目标和参考来源是否仍适用。
5. 运行 `npm run validate:content`、`npm run typecheck`、相关规则与浏览器测试及 `npm run build`。特别检查局部合成、重复点击、提示、重试、完成保存与主题解锁。
6. 在实际手机上检查小尺寸可读性、点击容错和横竖屏。通过后交付；公开部署仍须另行确认。

新增已支持玩法的关卡时增加自己的素材目录和 JSON，不修改找不同核心规则。新增玩法机制仍需实现对应模块，不用复杂配置代替程序逻辑。
