# 飞天文化影子配对首版 v001

原项目当时的方向支持（2026-11-03，历史记录）：2D手机仅横屏。主题选择、文化导览、玩法/关卡、游玩和结果共用`MobileLandscapeGuard`；帮助/设置与电脑窄窗口不受限，3D不共用此方向状态。手机初始竖屏不挂载内容，已开局竖屏保留实例并禁输入/停表，横屏恢复同局；找物仍暂停，玩家主动继续。`src/services/mobile-landscape.ts`按设备屏幕短边与触控能力识别手机，公共Phaser宿主通过独立`setBlocked`同步中断，不使用局内命令序号。旧手机竖屏排版、验收数字和截图保留作本规则调整前的历史记录，不作为当前手机竖屏可玩承诺。后续只维护手机横屏，竖屏仅验证提示与中断保局。

2026-11-01。用户已批准使用其交付的八张PNG开发一关影子配对，现已接入正式目录。本文件记录首版范围、素材事实及实际验收。

## 首关范围

- 关卡`music-apsara-shadow`位于“飞天、乐舞与服饰”主题。仅有一张彩色参照、四个干净剪影，只有一项与参照的轮廓完全对应；不将同一题包装成多关，也不声称完整飞天文化教学已经完成。
- 每局随机排列四个选项；放大、调整窗口或横竖屏切换保留本局与选项顺序。配置使用中性选项ID：`shadow-one`、`shadow-two`、`shadow-three`、`shadow-four`；正确项为`shadow-one`，不在面向玩家的选项名称中泄露答案。
- 不限时、无限提示与重试。错误选择留在本题，正确选择才完成并写入既有完成记录，不改旧存档结构。只沿用已确认的共用短音效；资源失败应显示错误与重试入口。
- 桌面与手机横屏按可用宽高排列参照和2×2选项；手机竖屏仅显示统一提示。原图保持完整比例与共同画布，可放大对照；按钮和图像在当前视口内，整页不滚动。复用现有敦煌面板和装饰按钮，选项可通过键盘操作。

## 素材技术审计

前四张为黑色RGB配合透明alpha的RGBA图，彩色图8也为RGBA；浅色面板会正常显示剪影，不能因某些查看器显示全黑就当成空图。三张标注图为1474×1474 RGB白底，红圈已烘焙进图，只作设计核对，不进入玩家选项。

使用共同坐标、`alpha >= 128`的二值前景比较，图1与图8的mask IoU为1.0、轮廓差异0像素；图2/3/4分别约为0.903248、0.951169、0.927295，因而只有一项正确。原始alpha灰度值并非逐像素相同，不能将轮廓一致写成整个文件或原始alpha一致。

标注核对仅在内存中取四边各110px留白以内的区域，忽略红线覆盖像素后比较黑色前景。5→2、6→3、7→4三组均完全对应；这个审计没有裁切或改写任何原图，也不需要为去掉红圈重新修图。

## 来源边界与重建

所有图片为开发者交付的AI教学示意，不是原壁画照片，不凭服饰、器物或文件名推断对应洞窟、年代、宗教身份或历史原貌。文化教学内容应另用明确资料说明；本关完成只表示完成一次轮廓观察活动。

首次导入：`python3 scripts/import-shadow-match-assets.py`，默认读取本次用户临时文件，也可传`--source-root <原图文件夹>`。脚本保留原文件名及SHA，不删除文件，不覆盖与既有字节不同的原稿、运行图或manifest；素材变化须另存版本。临时源文件不在时可从既有归档重建五张运行拷贝。

只读验证：`python3 scripts/import-shadow-match-assets.py --check`。验证原始八张及运行五张的SHA、字节一致、尺寸、alpha、唯一正确轮廓和三组标注对应，不依赖临时目录。素材审计结论不替代游戏交互、手机、存档及生产构建验收。

## 实现与验收记录

`src/games/shadow-match/`独立管理洗牌、状态、判定、布局和Phaser场景，复用公共`PhaserPlayer`生命周期。React通过`shadow-select`命令选择，通过快照展示反馈；HTML按钮覆盖在同源布局的图像上，可键盘操作。选项名称仅为本局A–D，不暴露答案标记。完成使用现有progress记录，保存失败沿用公共重试入口。

以下为方向调整前的历史实现：手机竖屏只在本玩法隐藏外层站点页眉，保留自身返回与题名，增加观察区高度；去掉各图顶部多余留白，保留标签与放大按钮。以298×409px画布计算，实际1254px方图的参照约110px、候选约83px；横屏高度有限时可打开独立双图对照窗。两图同步1/2/3倍和拖动，1倍完整显示；缩放不改变本局，未提供历史考据或新美术细节。
