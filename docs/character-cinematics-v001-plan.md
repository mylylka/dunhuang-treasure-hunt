## 范围与文件约定

沿用此前“独立样片先验证”的交付方式。只制作开场和藻井厅两段短演出，常规探索保留背后跟随。沿用现有建筑、道路和已确认环境资产；不扩展地图，不修改小游戏，不修改 AGENTS.md。

- 新动作源工程：`art-source/world/models/traveler-tripo/v002/traveler.blend`，同时保留导出登记。
- 新动作运行模型：`public/assets/world/traveler-tripo/v002/traveler.glb`。保留v001及用户原FBX/JPEG，模型外形、UV、贴图保持一致。
- Blender动作脚本：`scripts/build-world-traveler-gestures-v002.py`。动作按关键姿势手工设计，不通过随机参数生成。
- 镜头时序与触发规则：`src/world/character-cinematics.ts`；与现有 `runtime.ts`、`camera.ts`、`input.ts`、`art-sample.ts` 接口衔接，React只显示跳过等操作。
- 独立网页交付：`outputs/character-cinematics/v001/`；工作截图、视频、检查记录：`work/world/character-cinematics-v001-*`。不覆盖现有4192人物预览或正式构建。
- 自然环境、旧角色与旧模型的保护哈希在制作前登记、交付前复核。中间文件不自动清理。

## 已核对的实际项目条件

用户人物GLB有65根骨骼，包含肩、手臂、手指、脊柱、颈部及头部，可制作挥手、转身、张望、抬头动作。现有动画只有 Idle、Walk、Run、LookAround；没有挥手片段，不能把现有动作改名冒充挥手。

GLB没有表情变形目标、眼球骨骼或围巾控制骨骼。本轮按用户补充要求不处理这些内容；视线随头部朝向变化，不制作独立眼珠动作。

目前4192独立预览加载用户人物，正式 `WORLD_ART_SAMPLE.traveler` 仍指向旧人物。新演出先以用户人物制作独立可玩验证，不顺带切换正式地图的资产索引。

`runtime.ts` 现有状态为 follow / caisson / story。藻井互动范围为距世界坐标(-12,-17)小于2.6米；按F后才进入藻井观察。人物展示作为探索中的短演出处理，不冒充文化观察完成，不改变 visitedEvents。

## 分镜一：开场，约2.2秒

| 时间 | 人物与构图 |
| --- | --- |
| 0–0.25秒 | 小旅人站在道路起点，面朝镜头；中景看清完整头部、上身与抬手空间。镜头沿正常跟随方向稍靠近，避免绕人物转一整圈。 |
| 0.25–1.05秒 | 一次轻短挥手，头部有小幅呼应。身体重心稳定，不跳跃。 |
| 1.05–1.75秒 | 放下手，转身面向前路；转身过程中露出3/4侧面，镜头逐渐拉回正常跟随距离。 |
| 1.75–2.2秒 | 朝道路方向迈出很短的一步，并结束演出。实际位移限制在约0.3米以内，经现有碰撞检测；结束后不持续自动行走。 |

仅新探索从起点出发时自动播放一次。返回主题、返回小游戏、重试资源加载或回到起点不反复播放。开场前已有明确移动输入则直接进入探索。

## 分镜二：藻井厅，约2.5秒

仅第一次进入藻井观察范围并停步约0.35秒后触发。玩家一直移动则不启动，不在台阶或门廊强制停车。按钮“抬头看看”始终可主动使用。

| 时间 | 人物与构图 |
| --- | --- |
| 0–0.35秒 | 切入人物侧前方约30–40度的中近景，保留肩部和上方建筑线索。优先使用短切，避免在厅内快速绕柱旋转。 |
| 0.35–1.05秒 | 头部轻微左右张望，身体基本保持原位。 |
| 1.05–2.0秒 | 颈部与上胸配合，慢慢抬头看向藻井；保留脸和头顶空间。 |
| 2.0–2.5秒 | 短暂停留后回到正常探索镜头，保留“抬头看看”提示，等待玩家按F。 |

演出不自动进入藻井观察、不自动进入教学。演出期间按F直接进入已有藻井观察，不需要再按一次；移动或转镜头立即结束展示。该节点播放或被打断后，本次探索不再触发。

## 操作优先与镜头安全

- WASD、方向键、摇杆、Q/E和鼠标转镜头均可立即终止演出，并按原探索坐标方向处理输入，不能因展示镜头朝前而把前进变成后退。
- 提供一个“跳过”按钮，Escape结束演出。跳过不自动触发互动、不写入已完成文化事件、不擅自移动人物。
- 暂停、失焦、切到后台、横竖屏切换或离开页面时取消演出并清理输入；恢复时不接着自动行走。
- 减少动态效果开启时直接使用正常探索镜头，跳过自动转场。
- 藻井镜头按人物实际位置及朝向计算；左右两个安全候选位置经过现有墙体、柱子、屋檐碰撞检测。近景无法安全构图时跳过，不钻入模型或挤到脸上。
- 摄像机过渡逐帧检查，不能只检查起终点。结束后恢复原跟随偏角；人物位置只有开场明确设计的短步允许变化。
- 是否已播放与文化访问记录分开保存；不修改旧游戏或作品存档结构。

## 验证与验收

1. 在Blender查看挥手和抬头的正面、侧面、斜面；检查手穿脸、手臂穿衣、肩膀扭曲及脚滑。
2. 在真实网页录制两段演出，以及正常走入藻井范围后的自动触发过程；另提供开场正面、转身3/4侧面和厅内抬头截图。
3. 实测不同演出时刻按移动键、摇杆、Q/E、F、Escape和跳过按钮；验证即时交还操作、F只触发一次观察、退出后不重播。
4. 检查暂停/失焦/恢复、重新进入、资源失败重试、减少动态效果、桌面和手机横屏。循环经过藻井门口不能重复强制演出。
5. 检查两侧墙边、柱旁等位置的镜头与遮挡；安全构图不可用时保持跟随。
6. 运行相应类型检查、内容校验、规则测试、独立生产构建与串行浏览器验证。结果区分技术通过和用户对动作、节奏的视觉确认。

首版优先验证两段动作、构图和操作衔接。独立样片通过后再决定启用正式入口，不增加其他演出节点。
