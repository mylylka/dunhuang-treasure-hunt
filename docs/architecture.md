# 架构与继续开发

## 当前边界

React 负责导航、文化教学、玩法与关卡选择、提示面板、结果和长期记录；Phaser 4.2.1 负责当前关卡的图像和输入。主题引用玩法，不为每个主题复制玩法代码。正式目录目前有11关：4关找不同（`patterns-intro`、`patterns-lotus`、`patterns-scrolls`、`patterns-geometry`）、4关填色（`coloring-three-rabbits`、`coloring-lotus-camellia`、`coloring-grape-pomegranate`、`coloring-grape-lotus`）和3关拼图（`puzzle-lotus-ceiling`、`puzzle-three-rabbits`、`puzzle-twin-dragons`）。纹样主题七屏教学和三个玩法已接入，其余两个主题仍未开放。

## 屏幕与布局

应用占据当前动态视口（`100dvh`），首页、文化教学、玩法选择、该玩法关卡、游玩和结果是独立屏幕，使用 hash 路由切换。页面主体不纵向滚动；手机首页通过主题按钮切换封面。关卡目录按实际可用空间展示6、3或2张卡片，超过当前容量后分页；桌面常规视口同时展示六关，手机分页。帮助、教学正文和资料弹窗可在专用文字区域内部滚动。

`src/app/navigation.ts` 集中管理路由解析与路径。`#/` 是主题首页；`#/theme/patterns` 是文化导览；`#/theme/patterns/games` 是三种玩法；`#/theme/patterns/games/spot-difference` 是找不同关卡；`#/play/patterns-intro` 与结果地址保留稳定关卡ID。首页的主题链接始终进入导览，已有完成记录也不会跳过。教学顶部onSkip只导航到玩法选择；直接链接和游玩不受学习完成记录限制。旧游戏记录不受影响。

`ThemeCards`、`TeachingScreen`、`GameSelectScreen`、`LevelSelectScreen` 各管一层界面。三张主题卡共用相同3:2图框与14px图文间距；玩法选择的填色封面用cover铺满横版图框，此裁切仅作用于入口封面，游玩和参考图仍完整等比。正式关卡卡片提供封面、标题和按钮三个独立链接，可点击或键盘进入；筹备卡片没有链接。拼图目录按钮始终为“开始拼图”，已完成状态另外展示，结果页的重玩操作仍为“再拼一次”。主题卡不能让全高容器把标题推到屏幕底部。装饰按钮使用独立正文容器，正文以按钮真实中心对齐，方向符号不参与正文居中。

游玩页给导航、操作和提示保留空间，剩余区域交给 Phaser。运行器同时观察容器的宽和高，比较并排和上下两种排法，选择图片能显示得更大的方案，将两张完整图片按素材真实比例放入。旧首关为3:2，新增莲瓣团花、忍冬卷草与联珠与几何为1:1，比例由素材宽高派生。填色画布与较小参考配色图同屏，桌面以左大右小排列，手机按可用宽高紧凑安排；参考图可点击放大。线稿与参考图均按各自真实比例完整显示，不靠隐藏参考或页面滚动适配。容器尺寸变化只重新布局，不重建本局状态；手机横屏隐藏站点页眉与页脚，为画面留出空间。

## 内容入口

- 正式主题：`src/content/themes.json`。
- 素材索引：`src/content/assets.json`。
- 关卡：`src/content/levels/*.json`。Vite 自动发现该目录的 JSON；增加同玩法关卡无需改运行器。
- 配置和语义校验：`src/services/content-schema.ts`。
- 教学类型、内容和注册：`src/content/lessons/`；教学配置语法及引用校验：`src/services/lesson-schema.ts`。
- 公共接口：`src/types.ts`。

教学书按主题注册，包含稳定ID、内容版本、章节、面板、观察区域、提问和来源。第一主题七章为装饰部位、花叶纹样、几何纹样、动物纹样、组织方式、色彩、知识小考。教学整体使用有明亮底色、U03装饰边框与阴影的悬浮面板，面板内有“文化导览”标识和七个页签。图像热点和放大区域使用0～1比例坐标；通用教学组件不硬编码某个窟号或文字。新增面板主要修改内容数据，新增交互类型才扩展组件。

教学与小考均可跳过，学习完成记录不控制玩法、关卡或游玩入口。`introLevelId` 仅保留内容语义，不控制这层导航。图片以稳定素材ID引用，`version` 用于缓存标识；来源和占位状态随资源登记。玩法入口按实际正式目录开放，不显示空的可玩入口。填色目录显示四关；拼图合并六个规划位置，其中三关有正式内容、三关筹备中，都不依赖找不同完成记录。

## 找不同的显示方式

左侧为 A 图。右侧仍以 A 为底，只在配置区域内覆盖来自 B 的对应片段。差异数量来自数组长度；配置只有两项时，只出现两个视觉改动。图片完整等比显示；差异区域相对图片记录为 0～1 坐标，留白不参与命中。界面和玩法之间仅传命令和事件，不逐帧共享状态。参照图A和变化图B使用HTML标签，定位来自同一份画布布局；它们不再烘焙进Phaser文字纹理，避免画布缩放造成文字模糊。

当前首关使用用户交付的五处差异。运行 B 图预先以 A 为底、在五个区域内用物象蒙版合入 L02，排除其他重绘漂移；Phaser仍保留局部覆盖保护。“放大观察”是独立只读组件，切换A/B、通用2倍区域及上侧4倍细节，不改变发现状态；返回后继续在原图点击。

## 进度

`dunhuang:progress:v1` 保存完成记录与减少动效设置。每次完成幂等写入；重开只重置本局。无法保存时保留本次内存状态并显示重试。已有找不同完成记录继续兼容。填色提交后也可记录该关完成，但颜色作品不写入此键。

`dunhuang:learning:v1` 独立保存各教学书的内容版本、已访问章节与导览完成时间。每次进入主题从导览首页展示，已访问章节记录继续保留。小考六题均作答即可交卷，答错可交；若实际访问全部七章才记导览完成。跳过或只做小考不补齐未访问章节，不伪记学完。完成仅代表参与，不代表知识掌握；不保存考试分数。内容版本变化会使该书的旧完成记录失效，不影响游戏进度。读写失败如实提示并提供重试；损坏原记录在受保护写入前先备份，备份失败不能覆盖原数据。

## 玩法分发与填色

`LevelMetadata` 保存题名、学习目标、缩略图和来源等公共字段，`Level` 使用 `gameType` 区分找不同、填色与拼图配置。目录、结果和来源复用元数据；配置校验及运行器按玩法分发，不给填色套用差异字段。`src/games/coloring/` 独立维护区域命中、着色历史、渲染和Phaser场景。

填色每关引用配色参考、线稿和同尺寸区域ID图。区域图离线从线稿真实边界提取，RGB编码区域编号；不透明RGB像素编码区域ID，黑色编号0表示不可着色处。小碎区和外连白区可排除，因此完成条件是至少一个有效区域已着色后主动提交，不把区域数量当作作品完成度，也不要求参考图逐像素对齐。

每关提供12色与自定义颜色，擦除恢复未着色状态；修改进入本局撤销历史，清空重涂也是可撤销的一次操作。1×查看全图，2×/3×可拖动观察和点击。点击颜色约200ms柔和过渡并附短促触点反馈；应用或系统减少动效生效时立即换色并关闭装饰反馈。

`src/games/coloring/render.ts` 中的统一渲染器将区域颜色与原线稿叠合，保留线条。游戏、结果预览与PNG导出使用相同合成方法，导出全分辨率作品，避免结果图与游玩颜色不一致。运行时仅对显示纹理按当前尺寸高质量预缩，减少手机全图观察的细线断点；区域命中及作品导出仍使用原生像素。

`dunhuang:artworks:v1` 单独保存关卡ID → `artworkVersion` → 区域颜色、更新时间及提交时间。只存小型颜色映射，不存图片base64；旧通关记录结构不变。版本由线稿和区域图内容关联生成，新版本不套用旧区域编号；旧作品分支保留并如实提示。保存失败可重试，损坏原记录在受保护覆盖前先备份。撤销历史仅属于本局，不冒称刷新后还能恢复全部操作。

两关新找不同由 `scripts/import-pattern-levels.py` 重建：保留1254方形原稿，B经小幅相似变换配准，在五组确认区域内局部合入A，区域外0变化。忍冬卷草B的v002采用原B整圈圆润红瓣；一个差异可用主 `region` 和可选 `additionalRegions` 表达关联的多个部位，`getDifferenceRegions` 统一用于渲染裁切、命中与校验，同ID只计一次。主区域仍用于提示和发现标记，中央小花保持独立目标。来源目录记录矩阵、目标框、蒙版与校验值，不把整幅AI漂移视为额外找不同目标。

`patterns-geometry` 复用上述关联区域机制，四类目标分别对应菱形框内蓝绿纹、橙色圆珠内部、浅绿花叶边框和红地八角花纹。同类重复纹样共享ID，任一已登记位置命中后完成该类，不逐个累加边框上的重复单元。`scripts/import-geometry-level.py` 保留原稿和运行A，仅把B中确认纹样局部合入A，并向区域内部羽化；区域外像素检查与来源登记一同保存，不添加具体洞窟或年代归属。

三兔莲花、葡萄莲花的局部补线按用户本轮授权另存v002，已采用内置image_gen候选在确认范围内局部合成，完整纹样不重描；两关补线范围外均为0像素变化。重建后的区域数为三兔345、葡萄莲花510；其余莲花茶花511、葡萄石榴611。线稿、区域图与 `artworkVersion` 已同步，v001原稿、旧区域图和旧作品均保留。

三兔的三处兔身通过真实共耳通道同属ID132，圆内背景为ID125；保留兔身联动着色，没有虚画分隔线使三只兔子各自独立。葡萄莲花外方框补线闭合，阻止填色漏向纸外；部分飘带本来连通，仍保留联动，不声称每条细带独立。

归档目录是 `art-source/levels/coloring-three-rabbits/v002/` 与 `coloring-grape-lotus/v002/`，各保留 `ai-repair-full-output.png`、`reviewed-local-composite.png`、`repair-scope-mask.png`、`source-notes.json`、`processing.json`。来源记录含完整提示词、生成工具与处理范围。`scripts/import-coloring-repairs.py` 支持直接从正式归档重建，不依赖work缓存。以上为素材和区域技术结果，浏览器及生产构建检查结论另见验收记录。

## 拼图模块

`PuzzleLevel` 在公共元数据之外声明 `imageAssetId`、`mode`、`rows`、`columns` 和 `seed`。`mode` 区分 `rotation` 与 `jigsaw`；同一拼图模块共用图片加载、参考和必要操作，两个模式分别判定旋转朝向和拼片位置，不借用找不同的差异数组。

- `puzzle-lotus-ceiling`：3×3原位旋转，9块位置固定；初局有打乱朝向，每次点击顺时针90°，全部恢复才完成。
- `puzzle-three-rabbits`：3行4列共12片；`puzzle-twin-dragons`：4行5列共20片。内部切边使用共享的互补凹凸曲线，外边保持完整图像边界，不以矩形格子冒充不规则拼片。
- 图块由原图及程序裁切蒙版生成，可拖拽或选片后点击目标；放置正确才吸附，错误不计入进度。碎片区独立纵向连续滚动，整页不滚动，拼图区、进度与必要操作始终同屏。桌面滚轮、手机在碎片区空白处触滑，以及右侧原生滚动条都改变同一滚动偏移；拖片与滚动分开识别，裁切范围之外不能命中碎片。
- 提示只帮助定位，并将选中的目标碎片滚入可见范围，不自动把碎片放好或旋正。可无限重来，无计时、扣分或前置解锁。视口变化只重新布局，不重建局内状态；离开关卡后再进入重新开始。

`src/games/puzzle/` 保存纯规则、切边形状、布局和Phaser场景；`src/app/PuzzleScreen.tsx` 管参考与按钮，`src/runtime/PhaserPlayer.tsx` 复用原有引擎生命周期并按玩法分发。只有实际完成写入原 `dunhuang:progress:v1`，格式与旧记录不变，不另外保存半局拼图或迁移存档。

三张原JPG及带水印的旧运行图、处理记录保留在v001；当前1440×1440运行图为用户授权局部去水印的v002，候选、提示词、采用范围和范围外0像素变化核验存于各关 `art-source/levels/<id>/v002/`。`scripts/prepare-puzzle-retouches.mjs` 可从局部候选及旧运行图重建，不需额外生成碎片美术，也不把局部补绘或交付文件名当作具体文物细节的证据。

## 规划目录与结果页

## 教学安全区与图片观察窗

外层 `.lesson-panel` 只负责装饰，内部 `.lesson-content-surface` 是独立浅色内容面；安全边距覆盖真实装饰带，并将所有返回、资料、跳过、页签、图像工具及底部导航包含在内。页签使用内容字段 `tabLabel`，完整 `title` 继续用于正文和无障碍名称；不渲染逐页lead。窄屏可将七个短页签排成两行，每个标签本身保持单行。

`LessonImageViewer` 为全部19图卡提供同一个放大入口，支持全图、2×、3×、鼠标/触屏拖动、键盘方向移动、复位、Esc及焦点恢复；只改变观察视口，不修改源像素。有focus或highlights时，内页另提供看重点与位置标记。小考桌面左图右题，右侧独立滚动；手机按可用高度安排，不能隐藏固定控件来通过检查。

首页标题字体为官方LXGW WenKai的本地五字WOFF子集，3048字节，内部字体名Dunhuang Title。原件、OFL和SHA记录在 `art-source/shared/fonts/v001/`，运行字体和许可在 `public/assets/shared/fonts/`；`scripts/import-title-font.py` 可从原件重建。正常npm构建无需Python或字体服务，`index.html` 经Vite BASE_URL解析字体网址。
